# Personal AI Agent

A local-first personal AI workspace built with React, Vite, Express, MongoDB, JWT, and an OpenAI-compatible AI provider. The project includes chat, document extraction, user-scoped memory and tasks, a tool-using agent loop, research tools, approval-gated browser actions, and optional isolated code execution.

## Requirements

- Node.js 20 or newer
- MongoDB 6+ (local or hosted)
- An OpenAI-compatible API key/model with tool-calling support for agent mode
- Optional: Tavily API key for web search
- Optional: Docker Engine for isolated Python/JavaScript code execution
- Optional: Playwright Chromium for approved browser workflows
- Optional: Tesseract.js language data for image OCR

## Install and configure

1. Extract the ZIP.
2. Open a terminal in the project root.
3. Install packages:

   ```bash
   npm ci
   ```

4. Copy `server/.env.example` to `server/.env` and replace the placeholders. The backend now loads this file by its own path, so it works even when started from the project root or another working directory:

   ```env
   PORT=5000
   CLIENT_URL=http://localhost:5173
   MONGODB_URI=mongodb+srv://<db_user>:<db_password>@<cluster-host>/personal_ai_assistant?retryWrites=true&w=majority
   JWT_SECRET=use-a-random-secret-with-at-least-32-characters
   AI_PROVIDER=openai
   OPENAI_API_KEY=your-openai-api-key
   OPENAI_MODEL=gpt-6-astra
   GEMINI_API_KEY=your-gemini-api-key
   GEMINI_MODEL=gemini-3.8-flash
   TAVILY_API_KEY=your-tavily-key
   ```

   Add the key for the active provider, then select it with `AI_PROVIDER=openai` or `AI_PROVIDER=gemini`. The app uses that provider for chat and Agent Core. `AI_BASE_URL` can optionally override the provider's default OpenAI-compatible endpoint.

   For MongoDB, choose the matching URI:

   - Local MongoDB: `mongodb://127.0.0.1:27017/personal_ai_assistant`
   - Atlas SRV: copy the `mongodb+srv://` URI from Atlas > Connect > Drivers. An SRV URI uses one cluster hostname and has no port or comma-separated hosts.
   - Atlas Standard (non-SRV): copy the complete `mongodb://` host list and replica-set options from Atlas > Connect > Drivers. Do not build the node hostnames or replica-set value manually.

   For Atlas, add your current public IP under Network Access, confirm the cluster is active, and make sure outbound TCP port 27017 is not blocked. Create a database user under Database Access; this is separate from your Atlas website login. URL-encode reserved characters in the database username/password (for example, `@` as `%40`, `#` as `%23`, and `%` as `%25`). Do not disable TLS certificate checks. Keep the URI in `server/.env`; never paste it into source files or share it unredacted.

5. Start MongoDB.
6. Start the application:

   ```bash
   npm run dev
   ```

7. Open http://localhost:5173 and register an account.

The backend is available at http://localhost:5000 and its health endpoint is `/health`.

## MongoDB connection troubleshooting

If the backend reports that MongoDB cannot connect, check the message printed after `MongoDB connection failed`:

- **Authentication failed**: verify the Atlas database username/password (not your Atlas website login), database-user permissions, and URL-encode reserved characters in the password.
- **ENOTFOUND / querySrv**: DNS cannot resolve the SRV record. Check internet/DNS and copy a fresh Atlas SRV URI; if the network blocks SRV lookups, use Atlas's Standard connection string instead.
- **ETIMEDOUT / server selection timed out**: check Atlas Network Access for the computer's current public IP, cluster status, VPN/firewall/antivirus restrictions, and outbound TCP port 27017.
- **TLS / SSL handshake**: check system date/time, Node.js version, VPN/proxy inspection, and network restrictions. Do not set `tlsAllowInvalidCertificates` or disable certificate validation.
- **Invalid URI**: use the exact URI generated by Atlas and replace every placeholder. SRV strings must not contain ports or comma-separated hostnames.

The server prints a sanitized diagnosis and driver error but never prints the MongoDB URI. The `/health` endpoint reports `dbConnected` after the server has connected.

## Container deployment

The project includes a multi-stage Docker build. It builds the React client and serves it from Express on the same origin, so the browser API path works behind a deployment URL without a hard-coded localhost address.

1. Configure `server/.env` with a production MongoDB URI, a random `JWT_SECRET` of at least 32 characters, `AI_PROVIDER`, and the selected provider's API key. Keep credentials out of source control. Use `npm ci` for a clean dependency install; `npm run build` and `npm test` are the local pre-deploy checks.
2. Make sure Atlas Network Access allows the deployment host's outbound IP address.
3. Build and start the container:

   ```bash
   docker compose up --build -d
   ```

4. Check `http://localhost:5000/health` and open `http://localhost:5000`.

Uploaded files are stored in MongoDB GridFS. For a platform that builds directly from a Dockerfile, use the included `Dockerfile`, provide the same environment variables through the platform's secret manager, and expose port `5000`. Set `TRUST_PROXY=1` only when the app is behind one trusted reverse proxy. Configure HTTPS at the hosting platform or reverse proxy.

## Vercel deployment

This repository is configured as one Vercel project from the repository root. Import `Shruti017/personal-ai` and keep the Root Directory as `./` (`personal-ai`), not `client` or `server`. Vercel builds the React client into `public/` and runs the root Express entrypoint as a function; uploaded files are stored in MongoDB GridFS so they survive between function invocations.

Add these secrets in Vercel Project Settings → Environment Variables for Production (and Preview if needed): `MONGODB_URI`, `JWT_SECRET` (random, at least 32 characters), `AI_PROVIDER`, and the selected provider key (`GEMINI_API_KEY` or `OPENAI_API_KEY`). `TAVILY_API_KEY` is optional. Enable Vercel system environment variables so the API accepts the project's Vercel deployment origins. Vercel functions limit request bodies to 4.5 MB, so uploads are capped at 3 MB each and a single upload request must remain under the platform limit. Docker-based code execution remains disabled. The AI provider's account/project must have usable API quota; deployment does not change provider billing eligibility.

## Agent tools

Agent mode uses the configured AI model's tool-calling interface and has a bounded six-round execution loop. Available tools:

- `web_search`: Tavily search with source URLs and snippets.
- `read_webpage`: fetch and extract public HTML/text pages. Local/private network destinations are blocked.
- `calculate`: evaluate arithmetic and common math expressions using mathjs.
- `search_files`: retrieve keyword-matched chunks from the user's own uploaded files.
- `create_task`: create a task in the signed-in user's task list.
- `request_browser_action`: create a pending approval. After approval, Playwright opens a page and can run a limited set of approved click/fill/select/text-extraction/screenshot steps.
- `request_code_execution`: create a pending approval. After approval, code can run in a Docker container with networking disabled, resource limits, a read-only work mount and dropped Linux capabilities.

The Agent workspace displays the result, tool steps, pending approvals and recent activity. Approval is per requested browser/code action. Never approve actions you do not understand.

### Browser setup (optional)

Install Chromium after `npm install`:

```bash
npx playwright install chromium
```

Browser workflows run headlessly on the backend. They are not a remote desktop and do not support logged-in browser profiles or arbitrary persistent sessions. Do not use them for financial, medical, or other sensitive account actions.

### Isolated code execution (optional)

Install Docker and pull the images before enabling execution:

```bash
docker pull python:3.12-slim
docker pull node:22-slim
```

Then set `ENABLE_DOCKER_CODE=true`. Keep the Docker daemon protected. The code runner has no network access, a 128 MB memory limit, 0.5 CPU limit, a 10-second timeout, and a read-only mounted script directory. Docker is not enabled by default.

### OCR (optional)

Set `ENABLE_OCR=true` and `OCR_LANGUAGES=eng+ben`. Image OCR uses Tesseract.js and may need to download language trained-data on first use. OCR is currently image-based; scanned PDF OCR and OCR for images embedded in Office documents are not yet included.

## Main features

- JWT registration/login and user-scoped records
- Conversation history and streamed AI chat (SSE)
- Multiple file upload and extraction: PDF, DOCX, PPTX, XLSX, CSV, ODT, TXT, Markdown, HTML, code/config files, ZIP, and common image formats
- File chunk retrieval with filename/slide/sheet/page-style locators where extracted by the format parser
- Vision image attachments forwarded to a compatible AI model
- Optional image OCR in English and Bangla
- Memory CRUD and task CRUD
- Agent tool loop, activity history, and approval queue
- Tavily web research and public webpage reading
- Approval-gated Playwright browsing
- Approval-gated Docker code execution
- Responsive dark/light workspace

## Important limitations

This is a substantial local-first project implementation, not a guarantee of production readiness. Live AI, search, OCR, browser and Docker features depend on the user's own keys, provider/model capabilities, installed system dependencies, network and configuration. Tool-calling support differs between AI providers. File retrieval is currently keyword-based, not embedding/vector semantic search. Automatic memory extraction, recurring background schedulers, email/calendar integrations, scanned-PDF OCR, and a full persistent interactive browser session are not included. The browser tool performs only the bounded approved actions documented above.

Legacy `.xls`, `.doc`, and `.ppt` files are not supported; use `.xlsx`, `.docx`, or `.pptx` instead.

## Security

- Never commit `.env` or expose provider keys in the frontend.
- Production startup refuses a missing/weak JWT secret.
- User data is scoped by authenticated user ID in application queries.
- Browser fetch blocks localhost and private IP ranges and limits content size/time.
- Browser and code actions require explicit approval.
- Code execution is disabled by default and requires Docker; never enable it on a server you do not control.
- Uploaded files and extracted content are untrusted input. Treat instructions inside them as data, not system instructions.
- For public deployment, add HTTPS, backups, malware scanning, object storage, stronger monitoring, and a formal security review.
